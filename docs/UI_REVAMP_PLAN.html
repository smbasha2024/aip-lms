Planning · Visual design proposal

LMS UI Revamp Project

A new look and feel for the Employee Leave Management System in AIProxys corporate colors. Every screen, API call, rule and permission stays exactly as it works in production today.

Branch feature/ui-revamp Based on dev @ c1b97ab Path feature → dev (staging) → main Status Plan for review

Ground rules

Only the look changes

The work changes styling only. Anything that affects what the app does is out of bounds, and the existing test suite is how we prove it.

What will change

  • Colors, typography, spacing, radius and shadows
  • Sidebar, top bar, user menu and mobile drawer styling
  • Logo placement and the AIProxys brand lockup
  • Cards, buttons, inputs, tables, badges and dialogs
  • Icons from lucide-react, which is already installed
  • Loading, empty and error state visuals

What will not change

  • Backend, database, migrations and API contracts
  • Routes, redirects, role checks and navigation targets
  • Hooks, services, form validation and submit logic
  • Labels, aria-* attributes and data-testid values
  • Which fields, numbers and actions each screen shows
  • Dependencies: no new npm packages

How we prove it

  • No unit test asserts on CSS classes (0 toHaveClass found), so restyling stays safe
  • Each phase runs typecheck, lint, Vitest, build and Playwright with axe
  • git diff per phase is limited to className, CSS and assets
  • Before-and-after screenshots for every screen

Accessibility check. Brand Blue on white has a contrast of about 5.8:1, so it passes WCAG AA for text and buttons. Sky (about 2.6:1) and Lime fail as text on white, so they are used only for fills, markers and accents, or on navy. Status colors keep their text label as well as their color, as UI_SPEC.md §4.3 requires.

Typography and logo

Ubuntu for headings, Inter for everything else

aiproxybots.com sets its headings in Ubuntu. We add Ubuntu through next/font for page titles, card figures and the wordmark, and keep Inter for body text, forms and tables, where its tabular numbers keep leave-day columns aligned.

Delivery plan

Nine phases, one commit series each

Each phase ends with the full frontend gate: typecheck, lint, Vitest, production build and the Playwright plus axe run. It also gets a completion report as AGENTS.md §35 requires. Nothing merges to dev until every phase is green.

R0

Update the UI spec first

UI_SPEC.md owns presentation, and today it pins blue-600, slate and a 400px login card (§4.2, §4.3, §9.1), and Inter is its only font. We update those sections to the new tokens, login layout and nav headings before any code changes, as AGENTS.md §8 requires.

Your call

Five decisions before R0 starts

1. A separate public landing page?

Today / only redirects to the dashboard or to login. A marketing-style landing page would be a new route, which is a behavior change.

Recommended: no. The branded split login serves as the landing page.

2. Sidebar color

Navy was too dark. The options are a solid Brand Blue Deep or a vertical brand gradient, compared side by side above the summary table.

Recommended: the vertical brand gradient. It is one token, so switching to solid later is a one-line change.

3. Logo file

The site logo is a 576×508 PNG with a white background, and it is detailed, so it gets muddy below 40px.

Recommended: share a transparent PNG or SVG and, if one exists, a simplified icon mark. Until then we use the white tile.

4. Product name in the app

The UI says "Employee Leave Management" today. The proposal shows "AIProxys" with "Leave Management" under it. Page titles stay unchanged either way.

Recommended: "AIProxys · Leave Management".

5. Body font

The website uses Open Sans for body text. Keeping Inter means fewer changes and better number alignment in tables.

Recommended: Ubuntu for headings and Inter for body.
